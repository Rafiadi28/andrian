BUG #1: PERANGKAT DESA PREFILL NOT WORKING
───────────────────────────────────────────
Problem:    When editing a revisi for "jenis kredit perangkat desa", 
            the analis form didn't prefill with previous data
            → User had to input everything again ("jangan input dari awal")

Root Cause: Client-side prefill script couldn't match "perangkat desa" variants
            (PERANGKAT DESA, perangkat_desa, etc. not recognized)

Solution:   Implemented client-side normalization:
            1. Convert to lowercase: "Perangkat Desa" → "perangkat desa"
            2. Replace underscores/dashes: "perangkat_desa" → "perangkat desa"
            3. Match pattern: if strpos(normalized, 'perangkat desa')
            4. Populate 8 desa-specific fields

Status:     ✅ FIXED - All 6 variants now work

Test:       All prefill variants match correctly (6/6 PASS)


BUG #2: APPROVAL ROUTING CHAIN BROKEN
──────────────────────────────────────
Problem:    When kasubag_analis was cuti, system fallback to analis (OK).
            But if both were cuti, system didn't continue to kabag_kredit
            → Approval chain was stuck, couldn't escalate

Root Cause: Algorithm marked fallback targets as "visited" too early
            When fallback (kadiv_bisnis) was also in chain, loop broke
            because it was marked visited before being checked

Solution:   Conditional visited marking:
            • Only mark non-chain fallbacks as visited
            • Allow chain roles to be checked naturally in chain traversal
            • Proper fallback → chain escalation flow

Status:     ✅ FIXED - All 6 routing scenarios now work

Test:       All scenarios pass (6/6 PASS)

FEATURE #1: AUTO-ROUTING WITH CUTI FALLBACK
────────────────────────────────────────────
When approver is unavailable (cuti), system automatically routes to next available:

Fallback Chain:
  kasubag_analis (cuti) → analis
  kabag_kredit (cuti) → kadiv_bisnis
  kadiv_bisnis (cuti) → direktur_utama
  direktur_utama (cuti) → [BLOCK - manual intervention needed]

Integration Points:
  1. api/save_assessment_kepatuhan.php (after kepatuhan assessment)
     └─ Route from kepatuhan to next approver (normally kasubag_analis)
  2. includes/functions.php (in approval processing)
     └─ Route in approval flow when kasubag/kabag/kadiv decide
  3. analis/save_section.php (on analis form submit)
     └─ Route when analis submits for approval

Status:     ✅ IMPLEMENTED - All 3 entry points integrated


FEATURE #2: AUTO-SKIP AUDIT TRAIL
──────────────────────────────────
Every fallback decision is recorded for transparency:

Record Format:
  INSERT INTO approval_kredit 
    (id_pengajuan, level_approval, keputusan, catatan, is_auto_skip)
  VALUES (?, 'kasubag_analis', 'eskalasi_otomatis', 
          'Auto-skip: routed to analis', 1)

Purpose:
  • Track every auto-skip decision
  • Know which levels were bypassed
  • Reason for the bypass
  • Full audit trail

Example:
  When kasubag_analis is cuti:
  • Route pengajuan to analis ✓
  • Record approval_kredit with is_auto_skip=1 ✓
  • Shows kasubag_analis level was skipped ✓

Status:     ✅ IMPLEMENTED - All routes record auto-skip
